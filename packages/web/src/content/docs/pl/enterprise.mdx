CYBERVINCI does not offer a separate enterprise product, hosted control plane, sales channel, pricing plan, or managed SSO service. This page describes what an organization can do with the reviewed source and its own infrastructure.

## Deployment policy

Organizations should treat CYBERVINCI as a self-managed compatibility fork:

1. Build from a pinned, reviewed commit.
2. Distribute the resulting binary through an internal software channel.
3. Configure only approved AI providers and MCP servers.
4. Apply least-privilege tool permissions and network controls.
5. Keep credentials in the organization's existing secret-management system.
6. Validate updates in a staging environment before wider rollout.

External updates are disabled by default in this fork. Any release feed or publishing target must be configured explicitly by the operator.

## Data handling

CYBERVINCI keeps local configuration and session state on the machine where it runs. Model requests, tool calls, and enabled integrations can still transmit data to the providers or servers selected by the operator. Review each provider, MCP server, plugin, and command before enabling it.

Official OpenCode-hosted services, including OpenCode Zen, OpenCode Go, OpenCode Console, and hosted share pages, are separate services operated by the OpenCode project. CYBERVINCI only preserves compatibility with them. Their terms, retention, pricing, and availability are not controlled by CYBERVINCI.

For a local-only policy, disable hosted sharing:

```json title="cybervinci.json"
{
  "$schema": "https://opencode.ai/config.json",
  "share": "disabled"
}
```

See [sharing](/docs/share), [permissions](/docs/permissions), [providers](/docs/providers), and [configuration](/docs/config) before deployment.

## Identity and gateways

CYBERVINCI can use provider credentials and endpoints supplied through its normal configuration. If an organization needs SSO, a private AI gateway, centralized policy enforcement, or audit retention, those capabilities must be supplied and operated by the organization or an explicitly selected vendor. This repository does not claim to provide them as a managed service.

## Support

Use the local `README.md` and `CYBERVINCI.md` for build-specific guidance. Operational support belongs to the maintainer or team that supplied your source checkout or binary.
