---
title: GitHub
description: Run CYBERVINCI in GitHub Actions with operator-controlled artifacts.
---

The GitHub integration in this fork is self-hosted. It does not download or execute the OpenCode GitHub Action.

## Prerequisites

Before enabling the integration, the operator must provide both:

- a pinned GitHub Action reference built from this CYBERVINCI source tree, for example `owner/repository/github@<commit>`;
- a trusted CYBERVINCI executable already present in the runner workspace.

Set these variables before running the installer:

```bash
export CYBERVINCI_GITHUB_ACTION="owner/repository/github@<commit>"
export CYBERVINCI_GITHUB_BINARY="./.cybervinci/bin/cybervinci"
cybervinci github install
```

`cybervinci github install` refuses to generate a workflow when either variable is missing. The generated workflow passes the trusted binary to the composite Action explicitly.

## Manual workflow

Provision the binary with your own reviewed build or artifact process, then reference a pinned CYBERVINCI Action:

```yaml
name: cybervinci

on:
  issue_comment:
    types: [created]

jobs:
  cybervinci:
    if: contains(github.event.comment.body, '/cybervinci')
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
      pull-requests: read
      issues: read
    steps:
      - uses: actions/checkout@v6
        with:
          persist-credentials: false

      # Build or restore a reviewed CYBERVINCI binary here.

      - name: Run CYBERVINCI
        uses: owner/repository/github@<commit>
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          binary: ./.cybervinci/bin/cybervinci
          model: anthropic/your-model
```

The official OpenCode service names, provider identifiers, and environment variables remain unchanged where that service compatibility is required. They are not CYBERVINCI distribution channels.
